# クロススタック可視化 検証用「超最小」テストアプリ

VS Code拡張機能や静的解析ツールが、「React操作 → API → Laravelコントローラ → Service → Model → DB」というクロススタック（複数レイヤー間）の処理の流れを正確に検出・可視化できるかを検証するための、最小構成のテスト用サンドボックスです。

業務ロジックは一切含まれず、静的解析ツールがパスを拾いやすいプレーンな構造と、Xdebugによる完全な関数実行トレースの生成を満たすことだけを目的に構築されています。

---

## 1. 全体構成（モノレポ／マルチレポ両対応）

本プロジェクトは、フロントエンドとバックエンドが完全に独立したディレクトリに分かれており、単一のリポジトリ（モノレポ）としても、それぞれを別リポジトリ（マルチレポ）として分割しても動作するように設計されています。

### ディレクトリ構造
```text
.
├── sample.code-workspace  # VS Code マルチルートワークスペース設定
├── docker-compose.yml     # バックエンド起動用Docker構成
├── README.md              # 本ドキュメント
├── api/                   # バックエンド（Laravel 11 + PHP 8.4-cli）
└── web/                   # フロントエンド（Next.js 14+ + TypeScript）

```

### ワークスペースの利用（モノレポ / 同時開発時）

ルート直下にある `sample.code-workspace` をVS Codeで開くことで、マルチルートワークスペースとして `api/` と `web/` の両方のフォルダを同時に、独立したコンテキストで開くことができます。
これにより、クロススタック拡張機能が両方のソースコードを跨いで解析することが可能になります。

---

## 2. バックエンド仕様 (api/)

* **URLパス:** `routes/api.php` に定義（自動的に `/api` プレフィックスが付与されます）。
* **ポート番号:** ホスト側からは **`8080`** ポートで公開（※8000番の競合を避けるための設定。コンテナ内部では8000番で動作し、Dockerのポートフォワーディング `8080:8000` で中継）。
* **アーキテクチャ連鎖:** `Route` -> `UserController` -> `UserService` -> `User(Model)` -> `SQLite` の小さな密結合連鎖。
* **データ初期化:** コンテナ起動時に SQLite データベースが自動生成され、シーダーによって5件（起動ごとに累積）のダミーユーザーが自動挿入されます。

## 3. フロントエンド仕様 (web/)

* **テクノロジー:** Next.js (App Router) + TypeScript + React (Client Component)。
* **APIコール:** 静的解析ツールが追跡しやすいよう、ラッパーを通さず生の `fetch` を使用して、LaravelのエンドポイントURLを直接指定しています。
* **コンポーネント分割:** 静的解析がコンポーネントを跨いでパスを追えるよう、以下の3つに分割されています。
* `UserList.tsx` (GET `http://localhost:8080/api/users`)
* `UserDetail.tsx` (GET `http://localhost:8080/api/users/{id}`)
* `CreateUserForm.tsx` (POST `http://localhost:8080/api/users`)

## 4. セットアップ・起動手順

実機（ホストマシン）に PHP、Composer、Laravel 等の環境は一切不要です。すべて Docker 経由でクリーンに動作します。
（※ フロントエンドの起動には Node.js/npm が必要です）

### 4-1. バックエンド (Laravel) の起動

プロジェクトのルートディレクトリでターミナルを開き、以下のコマンドを実行します。

```bash
docker compose up -d --build

```

#### 重要：初回起動時の注意（ハングアップの防止）

初回の起動時は、コンテナ内部で `composer install` や依存パッケージの自動生成（Autoload Dump）が行われるため、利用可能になるまで数分かかる場合があります。

以下のコマンドを実行して**ログをリアルタイム監視**し、起動が完全に完了したことを確認してください。

```bash
docker compose logs -f api

```

ログの末尾に以下のメッセージが出力されれば、起動完了です。確認できたら `Ctrl + C` で監視を終了してください。

```text
[INFO] Starting Laravel artisan serve internally on port 8000 (Exposed to host via port 8080)
INFO  Server running on [[http://0.0.0.0:8000](http://0.0.0.0:8000)].

```

### 4-2. フロントエンド (Next.js) の起動

別のターミナルウィンドウを開き、`web` ディレクトリに移動して開発用サーバーを立ち上げます。

```bash
cd web
npm run dev

```

起動後、ブラウザで `http://localhost:3000` を開くと、UI画面が表示され、バックエンドのSQLiteから取得したダミーユーザーの一覧が表示されます。

## 5. 動作確認と受け入れ条件の検証

本アプリが正しく可視化ツールの検証要件を満たしているかは、以下の手順でテストできます。

### 検証1: 静的ルーティングの確認

コンテナ内で以下のコマンドを実行し、定義されている3つのルートが完全な JSON 形式で出力されるか確認します。

```bash
docker compose exec api php artisan route:list --json

```

### 検証2: Xdebugによる実行トレースの自動生成

ブラウザ、またはターミナル（PowerShell等）から、URLの末尾に `XDEBUG_TRIGGER=GO` というクエリパラメータを付与してAPIを叩きます。

**PowerShellでの実行コマンド:**

```powershell
curl.exe "http://localhost:8080/api/users?XDEBUG_TRIGGER=GO"

```

#### 生成されるトレースデータの確認

上記リクエスト送信後、**`api/.xdebug-trace/`** ディレクトリを確認してください。
`trace.xxxxxx.xt` という名前の数MBのファイルが出力されていれば成功です。

このファイルには、Xdebugの「フォーマット1（パース用タブ区切り形式）」で、リクエストがコントローラやサービス、モデルを通過した全関数の実行経路、メモリ使用量、タイムスタンプが完全に記録されています。可視化ツールにこのファイルを解析させて検証を行ってください。

## 6. デバッグログについて

プロダクトの内部を認識しやすくするため、各レイヤーを処理が通過する際に、以下のデバッグログが必ず出力されるようになっています。

* **Reactコンポーネント側:** ブラウザのF12開発者ツールのコンソールに `[React Component] ...` と出力。
* **Laravelバックエンド側:** ログ、または `docker compose logs api` 上に `[Route]`, `[Controller]`, `[Service]`, `[Seeder]` のプレフィックス付きで通過ログが出力。
